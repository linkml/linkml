Scala
=====

Overview
--------

The Scala generator writes Scala 3 classes for the data of a LinkML schema: one ``.scala`` file for
each class, enum and type. The generated code is compatible with the Scala runtime of ohi LinkML.

.. code-block:: bash

   gen-scala personinfo.yaml --package org.example.personinfo -d src/main/scala/org/example/personinfo
   linkml generate scala personinfo.yaml --package org.example.personinfo

Without ``--output-directory`` (``-d``), all files are printed, each after a ``// FILE`` comment
with its name. With it, the files are written straight into that directory, without a
subdirectory for the package. Files with the same name are replaced.

Maintained in ohi LinkML
------------------------

.. important::

   The generator itself is **not implemented in this repository**. This is a wrapper
   around the Scala generator in `ohi LinkML
   <https://linkml.ohi.dev/>`_.

   Please report any bug reports or feature requests at
   https://github.com/NeverBlink-OSS/ohi/issues

   You can also try the generator without installing anything in the
   `in-browser playground <https://linkml.ohi.dev/playground/?target=scala>`_.

When reporting bugs, please include the versions of both linkml and ohi LinkML.
You can find them by running ``gen-scala --version``.

What gets generated
-------------------

.. list-table::
   :header-rows: 1
   :widths: 40 60

   * - LinkML
     - Scala
   * - Class
     - ``final case class``. If other classes extend it, an ``abstract class``, and a
       ``final case class`` named ``...Impl``
   * - Abstract class
     - ``abstract class``
   * - Mixin
     - ``trait``
   * - ``is_a`` and ``mixins``
     - ``extends``
   * - Slot
     - Field of each class that uses it, in camel case
   * - Enum
     - ``sealed abstract class``, with a ``case object`` for each permissible value
   * - Type
     - ``type`` alias for the Scala type of its base type
   * - ``emit_prefixes``
     - ``Prefixes`` object, unless ``--no-emit-prefixes`` is given

The full mapping is described in the `ohi LinkML documentation
<https://linkml.ohi.dev/docs/generators/scala/>`_.

Packages and imports
^^^^^^^^^^^^^^^^^^^^

All files are in the package given by ``--package`` (``example`` by default).
Classes, enums and types from imported schemas are generated into the same package.

Removing old files
^^^^^^^^^^^^^^^^^^

When a class is renamed or removed from the schema, its old file stays in the output directory,
and usually stops the code from compiling. Pass ``--clean`` to delete the ``.scala`` files that
ohi LinkML generated earlier before writing the new ones. Only files that start with the
``// Generated by ohi LinkML`` header are deleted, so files you wrote yourself are kept.

Using the generated code
------------------------

The generated code needs the Scala runtime of ohi LinkML, ``eu.neverblink.linkml::runtime``,
in the same version as the ohi LinkML that generated it. ``gen-scala --version`` shows it. The
runtime is published for the JVM, Scala.js and Scala Native. For example, with ohi LinkML 0.18.7:

.. code-block:: scala

   // sbt
   libraryDependencies += "eu.neverblink.linkml" %% "runtime" % "0.18.7"

   // Mill
   def mvnDeps = Seq(mvn"eu.neverblink.linkml::runtime:0.18.7")

   // Scala CLI
   //> using dep eu.neverblink.linkml::runtime:0.18.7

Limitations
-----------

The schema has to be a path to a local file. ohi LinkML reads it and resolves its imports
from disk itself, so a URL or an already-parsed ``SchemaDefinition`` is refused.
